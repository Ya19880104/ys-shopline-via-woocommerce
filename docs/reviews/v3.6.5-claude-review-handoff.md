## Independent review result

The vendor report and Claude's primary diagnosis are correct:

1. WooCommerce Subscriptions only recognizes an initial parent-order payment when its previous status is one of the native unpaid statuses (`pending`, `on-hold`, or `failed`).
2. A SHOPLINE asynchronous payment can instead complete through `ys-confirming -> processing/completed`, so WCS skips its normal subscription activation path.
3. `exclude_from_payable_statuses()` did not cause this defect. `ys-confirming` was not in WCS's default unpaid list, so removing it there was already a no-op for this decision.
4. Renewal orders remain outside the confirmation lifecycle because `enter_confirmation()` already excludes orders for which `wcs_order_contains_renewal()` is true. The defect and this fix are limited to initial/parent orders.

One detail needs more precise wording than the original report: WooCommerce writes `date_paid` when the new status is that order's computed payment-complete status. For a physical order this is normally `processing`; an administrator who assigns that status is intentionally declaring the order paid, and WCS activation is native WooCommerce behavior. If the destination is not the computed paid status, `date_paid` remains empty and this compatibility callback refuses activation.

## Production change

`YSPaymentConfirmation::init()` now registers the WCS 6.9+ filter `wcs_is_subscription_order_completed` with the documented five arguments.

The callback returns true only when all of these conditions hold:

- WCS has not already returned true.
- The previous order status is exactly `ys-confirming`.
- The parent is a real `WC_Order`.
- The destination is `processing`, `completed`, or the filtered WooCommerce payment-complete status.
- The parent order already has `date_paid`.

It does not add `ys-confirming` to payable statuses and does not call a subscription's `payment_complete()` directly. WCS remains responsible for ended/cancelled guards, activation, date handling, and Action Scheduler renewal events.

Version and changelog are updated to 3.6.5. There is no database migration and no checkout JavaScript change.
