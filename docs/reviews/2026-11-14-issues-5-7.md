## Findings and Policy

- #5 confirmed: the original code completed an order changed from TWD 100 to TWD 200 using the original TWD 100 payment. The new regression failed before the fix (1117 PASS / 1 FAIL).
- All automatic completion paths now validate the remote trade, full reference, method, sent amount/currency and current order against the persisted original request. Missing/mismatched evidence retains the request and safe received evidence, flags manual review, and blocks repayment. It does not fabricate original evidence from the current order. Legacy orders without sufficient original evidence require review.
- The explicit zero-total subscription CardBind authorization exception still requires the original request and matching remote amount. A read-only sandbox query of existing zero-total order 12189 returned SUCCEEDED with order/paid amount 10100 TWD minor units. No new CardBind transaction was made.
- Incomplete immediate-create responses are queried once by trade ID; a query failure does not invent missing evidence. Complete responses incur no extra query.
- #6 confirmed: a customer-only card notification previously wrote the same instrument to every unbound subscription for that user. Requests now capture the parent order, exact reference, user/customer, selected instrument when present, and specific subscription IDs. Only validated payment evidence can complete that binding. Duplicate/late events cannot overwrite an existing card.
- A richer exact paid event may finish a pending binding without running payment completion again. Generic customer-card events still populate the user token store but cannot assign subscription cards.
- Unbound renewals now pause for review rather than charging the user's default card. Changing a default card does not change existing bindings. The existing fallback after an explicitly declined bound-card charge is retained. Binding requests are excluded from renewal metadata copying.
- #7: merchant setting location, all four credentials per environment, URL-specific Webhook Sign Key, supported routes/events, signature/timestamp checks, payment/refund semantics, valid document links, and historical candidate status are corrected.
